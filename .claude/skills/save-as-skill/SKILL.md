# 방금 한 방식을 스킬로 저장하기

사용자가 대화에서 방금 한 작업 방식을 다음에도 그대로 쓰고 싶어 한다. 그 방식을 `.claude/skills/<이름>/SKILL.md`로 저장하고 커밋·푸시한다.

## 1. 무엇을 저장할지 정리

대화를 되짚어 다음을 뽑는다. 추측으로 채우지 말고 실제로 한 것만 쓴다.

- **목적**: 이 방식이 해결하는 일 (한 문장)
- **입력**: 사용자가 매번 주는 것 (예: 강의 자료 PDF, 주제, 글 초안)
- **단계**: 실제로 거친 순서. 도구·파일·명령어가 있었으면 그대로
- **고정값 vs 변하는 값**: 매번 같은 것(형식, 말투, 체크리스트)과 매번 바뀌는 것(주제, 파일 이름)
- **사용자가 고쳐 준 부분**: 대화 중 "이건 이렇게 해 줘"라고 수정한 내용. 가장 중요하다.
- **결과물 형태**: 출력 형식, 길이, 저장 위치

"방금 한 방식"이 어느 부분인지 모호하면(대화에 작업이 여러 개면) 어떤 작업인지 한 번만 묻는다.

## 2. 이름과 설명

- 이름: 영어 소문자와 하이픈, 짧게 (예: `care-plan-outline`, `lecture-summary`). 기존 `.claude/skills/` 안 이름과 겹치면 다른 이름을 고른다.
- description: 언제 쓰는지 한국어와 영어 트리거 문구를 함께 넣는다. 사용자가 실제로 할 법한 말을 2~4개 적는다.

## 3. SKILL.md 작성

```markdown
---
name: <이름>
description: |
  <무엇을 하는지 한 줄>. Use when the user says "<트리거1>", "<트리거2>".
---

# <제목>

## 입력
## 단계
1. ...
## 지켜야 할 것
- (사용자가 고쳐 준 내용, 말투, 형식)
## 결과물
```

- 단계는 다음에 다른 대화에서 읽어도 따라 할 수 있게 구체적으로 쓴다. "적절히 정리" 대신 "표 3열: 진단 / 근거 / 중재"처럼.
- 이번 대화에만 있던 고유 내용(특정 환자 정보, 개인정보, 비밀번호, API 키)은 넣지 않는다.
- 사용자의 응답 선호(예: 쉬운 예시 먼저, 끝에 3줄 요약, 과제는 단계별 안내만)가 이 작업에 해당하면 "지켜야 할 것"에 넣는다.
- 길어지는 예시나 템플릿은 `references/` 아래 별도 파일로 뺀다.

## 4. 저장 전 확인

만들 스킬의 이름, description, 단계를 짧게 보여 주고 이대로 저장할지 묻는다. 사용자가 "그냥 저장해"라고 했으면 묻지 않고 저장한다.

## 5. 저장과 커밋

1. `.claude/skills/<이름>/SKILL.md` 작성 (저장소 루트 기준)
2. 현재 작업 브랜치에 커밋: `Add <이름> skill`
3. 푸시 (`git push -u origin <현재 브랜치>`)
4. 사용자에게 알린다: 스킬 이름, 부르는 법(`/<이름>` 또는 트리거 문구), 그리고 **새 세션부터 자동으로 인식된다**는 점. 클라우드 세션은 시작할 때 저장소를 새로 받으므로, 이 브랜치가 main에 합쳐져야 다른 브랜치에서 시작한 세션에도 나타난다.

## 고칠 때

사용자가 "그 스킬 수정해 줘"라고 하면 새로 만들지 말고 기존 SKILL.md를 읽고 고친 뒤 같은 방식으로 커밋한다.
